# LIT Buy — Legacy and dead-code inventory

This is a **non-destructive static inventory** for future Claude Code/human review. It maps likely sources of confusion without deleting, moving, renaming, or refactoring anything. Classification is about the feature-frozen Alpha critical path, not about product value.

## Method and confidence

Inspection covered `src/services`, `src/data`, `src/components`, `src/routes`, `src/providers`, `scripts`, tests, and documentation references. Evidence came from route/component imports, direct text/reference searches, structural no-mock tests, package scripts, and the current Alpha/runbook documents.

Simple text/import searches cannot prove runtime reachability under TanStack file routing, dynamic imports, generated code, re-exports, or indirect callbacks. Therefore “DEAD CANDIDATE” means **candidate for deeper review**, never permission to delete. Before any removal, rerun TypeScript-aware dependency analysis, build/tests, route generation, and manual smoke coverage.

2. Separate “legacy but used” from “dead”: deleting fixture data or broad services would break visible non-critical routes.
3. Review high-risk demo surfaces for security/production implications later, without treating them as Alpha blockers now.
4. Reconcile historical documentation only after the read-only audit; current authority already prevents it from redefining state.
